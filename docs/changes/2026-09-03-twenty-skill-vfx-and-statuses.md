# 二十式技能、状态与特效重制

## 目标

删除现有 100 个换色技能,重做为 20 个手工设计技能。每个技能同时具备
独立数值、战斗机制、状态结算、施法节奏、持续特效和命中特效。

## 视觉参考

- 参考 `achrefelouafi/LinearAbiltyCastingThreeJS` 的核心方法:每招先确定独立
  轮廓,再组织蓄力/行进/命中/余波阶段;发光线条采用宽光晕与窄亮芯分层,
  范围技使用过冲回弹,命中后保留短暂地面痕迹。
- 本项目是固定机位的 Bevy 2D 回合战斗,不照搬自由瞄准、3D 模型、GLSL
  后处理和 GPU 粒子框架;只移植能服务当前玩法与构图的演出原则。

## 范围内

- 删除十元素 x 十形态的 100 个换色组合与旧参数化圆光特效。
- 新建独立 `skill_vfx.rs`,负责二十套分阶段演出。
- 建立统一状态模型,负责中毒、灼烧、冰冻、震慑的施加、刷新、结算和清除。
- 20 招继续进入开局随机技能、战利三选一、技能菜单和行囊。
- 离屏捕获连续播放全部 20 招,并专门证明中毒、冰冻、灼烧结算。
- 更新 `STRUCTURE.md` 与本文件的验收证据。

## 明确不做

- 不迁移 Bevy 版本,不增加第三方粒子或战斗框架。
- 不把自由瞄准和鼠标施法移植到当前回合制战斗。
- 不保留旧 100 技 ID 或兼容转换层;当前游戏没有存档序列化契约。
- 不为本轮增加音频依赖。

## 假设

- 技能特效使用程序化 2D 网格、精灵、现有柔光纹理和动态光,不新增位图素材。
- 状态数值以当前 20–40 分钟肉鸽战斗节奏为基准。
- 冰冻和震慑都跳过一次行动,但只有冰冻触发 Boss 的一回合抗冻。
- 捕获专用脚本可以直接驱动真实技能 VFX 接口,不改变桌面玩家入口。

## 状态结算

- `中毒`:敌方回合开始结算,可以在行动前毒杀。最多 3 层,重复施加增加
  层数并刷新 3 回合;Boss 每回合毒伤不超过最大生命 8%。
- `灼烧`:敌方行动结束后结算。重复施加提高伤害并延长持续时间,上限 5 回合。
- `冰冻`:阻止敌人下一次行动,触发后冰层碎裂并清除。Boss 解冻后获得
  1 回合冰冻免疫,避免无限控制。
- `震慑`:雷系控制,跳过一次行动,但不触发 Boss 的冰冻免疫。
- 结算顺序:中毒 -> 死亡检查 -> 冰冻/震慑 -> 敌方行动 -> 灼烧 -> 死亡检查。
- 敌方信息栏持续显示状态层数、伤害和剩余回合。
- 中毒、灼烧、冰冻都有常驻敌身特效和独立的回合触发动画。

## 行为场景

### Requirement:持续伤害顺序可预测

WHEN 敌人同时带有中毒和灼烧进入自己的回合,
THEN 中毒先结算且可以阻止行动;敌人若仍存活则行动,随后结算灼烧。

### Requirement:控制有反馈且不能永久锁 Boss

WHEN 普通敌人被冻结或震慑,
THEN 下一次行动被跳过并播放对应破碎或放电反馈。

WHEN Boss 的冰冻被消耗,
THEN Boss 获得一回合抗冻,其间再次命中冰冻只显示抵抗反馈。

### Requirement:技能画面可辨认

WHEN 二十技能按顺序连续播放,
THEN 每一招都有独立主体轮廓,并完整呈现蓄力/行进/命中/余波中的至少三段。

## 验收标准

- `cargo fmt --check` 退出码为 0。
- `cargo check` 与 `cargo build` 退出码为 0。
- `cargo test` 通过状态时序、叠加、致死、Boss 抗冻及二十技能唯一性测试。
- 20 个技能名称与 `VfxStyle` 均唯一。
- `rogue-skill` 生成 900 帧、30 FPS、30 秒证明视频。
- 从证明帧生成 20 招接触表,每招主体轮廓可辨认。
- 单独截图证明敌方状态栏、常驻状态特效以及中毒/灼烧回合伤害。
- 捕获日志无资源缺失、层级警告和渲染错误。

## 风险

- 最大风险是 20 招在 2D 画面里同时追求差异和可读性。通过统一分阶段动画
  组件、限制每招实体数量,并逐招截图抽查控制。
- 状态致死发生在敌方行动的前后两个时点,容易与胜利转场重复。用纯函数单测
  锁定结算顺序,再用捕获验证实际回合日志。
